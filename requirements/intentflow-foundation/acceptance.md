# 验收标准

- [ ] 面对模糊产品想法时，一次只提出一个最高影响问题。
- [ ] 能先读取本地证据，再决定是否需要询问用户。
- [ ] 用户回答被写入 `decisions.md`，不会只留在聊天中。
- [ ] 未解决问题被写入 `open-questions.md`。
- [ ] 生成可观察的 `acceptance.md` 条件后再交接给下一流程。
- [ ] 当下一步已经清晰时停止追问。
- [ ] 输出明确区分用户确认、助手建议和未验证假设。
- [ ] 宽泛用户标签不会被自动当成已锁定的 MVP 细分。
- [ ] 用户委托 AI 提出的默认方案在确认前不会变成硬验收条件。
- [ ] 用户给出的时间期限被记录为交付约束，而不是产品有效性的证据。
