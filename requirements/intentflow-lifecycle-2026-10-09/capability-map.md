# IntentFlow 产品全流程能力地图

## 产品链路

| 能力 | 责任 | 当前状态 | 目标产物或可观察行为 |
| --- | --- | --- | --- |
| 入口路由与上下文归档 | 定位同一需求目录，读当前版本、决策和资料，决定下一模块 | 已有基础 | 所有阶段复用 `requirements/<name>/`，不另开同义需求目录 |
| 意图澄清 | 只问会改变后续工作的最高影响决策 | 已有 skill | 确认写入 `decisions.md`；未决项留在 `open-questions.md` |
| 证据挖掘 | 以具体案例收集反馈/公开资料，做案例整理、痛点聚类、替代方式对照和机会判断 | 第一版已建立 | 需求简报、来源登记、洞察 Markdown；HTML 洞察页按需生成；模拟材料不能当证据 |
| 需求文档 | 把背景、目标、范围、详细规则、边界、可选埋点写成可评审 PRD | 第一版已建立 | `product-prd`、PRD 模板、结构校验器 |
| 原型与高保真设计 | 表达页面、状态和交互；与 PRD 对齐 | 第一版规范已建立 | `product-prototype` 与现有 Figma 链路 |
| 业务与交互流程 | 表达业务分支、页面跳转和关键对象状态 | 第一版规范已建立 | `product-flows` 与可审查源文本 |
| 浏览器内评审 | 预览、编辑、保存和复制产物 | 第一版已建立 | 本地评审页、版本保护、图片复制和离线下载 |
| 截图与导出 | 从真实渲染生成原型/流程图截图并管理产物 | 第一版已建立 | Playwright 截图、缓存和归属清单 |
| 功能验收 | 把 PRD 和原型拆为主路径、边界、视觉和埋点检查 | 第一版已建立 | `product-acceptance`、浏览器状态与 `qa/results.md` |
| 数据分析与迭代 | 从真实数据计算指标、分析漏斗与差异并提出下一步 | 第一版已建立 | `product-analytics`、指标记录契约与 CSV 漏斗计算器；复杂分群/实验分析待扩展 |
| 安装、诊断与跨平台运行 | 初始化、依赖检查、预览和导出服务 | Windows 第一版已建立，macOS 入口已提供 | CLI、doctor、bat/command 入口；跨平台实机验证待补 |
| 交接与同步 | 保存当前版本、已定决策、文件索引和下一步 | 第一版契约已建立 | 需求目录模板、状态和 QA 记录 |

## 模块边界

1. 需求目录中的决策与证据是产品判断的依据；PRD、原型、流程图、验收与数据报告都要链接到同一需求。
2. `personal-grill-me` 不写 PRD；证据研究不把外部观察自动变成用户决策；数据分析不把相关性写成已证实原因。
3. 高保真设计默认接入现有 Figma 能力；交互式 HTML 原型可以作为不依赖设计工具的可评审产物。两者共存时要检查页面和状态一致。
4. Markdown 是 PRD、验收和分析的正式记录；交互式 HTML 按需生成。浏览器编辑要回写 Markdown 或产生明确的待合并变更，需有路径权限边界和版本校验。
5. 共用运行工具放在 `scripts/`，各需求只保存自身产物和证据；不用的产物目录不预建。
6. 可选设计工具通过适配层接入；Figma 是当前已建立的主路径，其他工具不强制每个需求安装。

## 细项覆盖清单

| 模块 | 需要覆盖的细项 | 完成判据 |
| --- | --- | --- |
| 需求研究 | 公开渠道检索、原声留痕、主题聚类、竞品对照、机会与反证 | 每条重要结论可回到原始材料；无法访问或样本不足时明确写缺口 |
| PRD 采集 | 目标用户、问题场景、核心改动、成功结果、已有材料、范围边界 | 关键缺口被澄清或作为具名假设记录，不把方便的默认值当决定 |
| PRD 内容 | 版本、背景证据、目标指标、范围、共享规则、页面/状态详细方案、按需埋点与时序 | 有统一结构，章节按需求规模裁剪，跨页规则不重复散落 |
| PRD 机械检查 | 必要章节、编号与表格结构、空值、原型映射、边界与待确认口径 | 校验器给出可定位错误，不能以“校验通过”代替内容评审 |
| 原型 | 多页面/多状态导航、可操作交互、嵌入预览、页面识别 | 核心路径能由用户操作，PRD 每个关键状态可找到对应视图 |
| 图表 | 业务流程、页面跳转全图、关键对象状态/时序、可复制的源文本 | 路径与状态一致；标签、连线、节点在实际尺寸下无重叠或越界 |
| 评审界面 | 文档与原型双栏、懒加载、缩放、页面联动、编辑、表格操作、撤销重做 | 默认阅读清楚；编辑和恢复行为可复现，刷新边界明示 |
| 复制与保存 | 正文和图片一并复制、受控文件回写、修订冲突检测、降级说明 | 复制后图片可见；保存不会覆盖目录外文件或静默丢图 |
| 截图导出 | 浏览器真实渲染、单页/批量、缓存、进度、文件归属清单 | 重复导出可复现，清理只触及本工具登记的文件 |
| 验收 | 主路径、异常边界、视觉状态、可选埋点；状态过滤、折叠、进度、导出 | 每项可记录未测/通过/失败/跳过，状态可恢复并带证据 |
| 数据复盘 | 数据接收、时间窗、指标定义、漏斗、分群、趋势、可能原因、行动项 | 计算可追溯；缺分母/基线时不编百分比或涨跌 |
| 运行工具 | 初始化、更新保护、运行环境、预览服务、截图服务、诊断、跨平台与按需启动、端口冲突恢复 | 重复运行安全；项目配置和用户产物不会被安装器覆盖 |
| 会话交接 | 最新产物清单、确认决策、未决问题、风险、下一步 | 新会话无需完整聊天记录即可继续 |

## 建议实施顺序（助手建议）

1. 固定需求目录与产物契约，完成 PRD、验收和分析三个内容技能及其校验。
2. 建立原型、业务流程、交互流程和 Figma 对齐规则。
3. 建立浏览器评审与截图导出运行层，先支持 Windows，再核验 macOS。
4. 用一个真实案例贯穿需求挖掘、PRD、原型、验收和数据分析；未发生的上线数据只能用显著标注的演示数据测试格式。

顺序是实现建议，不代表已完成或用户已批准具体技术选型。
