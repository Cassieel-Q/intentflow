# IntentFlow 需求洞察交付物设计

## 目标

把需求挖掘从一份简短记录升级为可评审的洞察交付物。正式记录为 Markdown；按需从同一份 Markdown 和配套资料表生成独立 HTML。HTML 是阅读与演示视图，不另立产品结论。

## 输入与边界

- `research/demand-findings.md`：正式结论，固定八个二级章节。
- `research/feedback.csv`：逐条反馈或模拟反馈，必须标明 `evidence_type`；真实反馈必须有可追溯 `source_id`。
- `research/products.csv`：公开产品参考，记录公开页面 URL、观察到的能力及无法核实的部分。
- `source.md`：所有真实资料的来源、发布日期、查阅日期、适用范围和局限。
- 模拟材料只能检验聚类、报告结构和视觉呈现；不能用于宣称真实痛点频率、情绪分布或市场规模。

## 报告章节

1. 洞察总览：研究对象、场景、核心研究问题和结论状态。
2. 场景与材料：具体情境、资料渠道、样本边界与模拟材料声明。
3. 反馈与聚类：逐条来源、反馈主题、聚类依据、反例与偏差。
4. 问题与归因：观察到的困难、可能机制、其他解释及证据强度。
5. 公开产品参考：产品公开能力、入口与限制；功能存在不等于效果已验证。
6. 首版需求收口：候选机会、取舍和哪些仍是建议；不得直接变成已确认 PRD。
7. 验证与指标：下一步验证设计及指标的分子、分母、时间窗。
8. 待确认结论：能确认、不能确认、待用户选择和后续动作。

## HTML 视图

- 深色但以 IntentFlow 自己的视觉语言实现：固定左侧章节导航、顶部阶段指示、主视觉概览、显著资料状态横幅、统计卡片、反馈与产品卡片、正文分区。
- 卡片数字只来自配套资料表；模拟反馈的数字直接标为“模拟条数”，真实反馈与模拟反馈分开展示。
- 公开产品卡片必须可点击到原始公开页面，卡片中显示“观察到的能力”和“尚未核实”。
- 提供章节定位、反馈主题筛选、模拟材料显示/隐藏、复制结论和下载反馈表。
- 文档在无网络时可打开；外部产品链接需要联网。手机宽度下导航转为顶部折叠菜单。

## 验证

- 用非案例化测试夹具确认标题和章节由输入生成、无硬编码需求名。
- 测试缺来源的真实反馈被拒绝；混合数据分开计数；缺产品时显示空状态，不伪造参考。
- 浏览器检查导航、筛选、复制和布局；检查正式 Markdown 不被 HTML 生成器改写。
