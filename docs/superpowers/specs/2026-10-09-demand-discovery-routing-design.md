# IntentFlow 需求挖掘路由设计

## 状态与目标

用户于 2026-10-09 确认：需求挖掘采用“Grill-Me 按需澄清 → 公开证据按需验证 → 需求产出”的路由。目标是让模糊想法得到必要澄清，让需要验证的判断得到可追溯证据，同时允许清晰且证据充分的小变更跳过前两步。

## 设计

1. **入口判断**：读取需求目录与已有材料。若未解决的产品决策会改变目标用户、可见行为、范围、数据或验收，则调用 `personal-grill-me`。若用户与问题已足以确定检索范围，而痛点、竞品或机会判断仍需外部依据，则调用 `demand-evidence-research`。两者都不需要时，直接进入下一交付物。
2. **意图澄清**：沿用一次一个最高影响决策、确认后持久化、区分用户确认/建议/假设的现有契约。研究可以在澄清后开始；若可做有用的宽范围资料扫描，可先扫描，但不能据此替用户确定细分人群。
3. **证据验证**：优先使用用户已有材料和可核验的公开资料，记录来源、日期、对象、样本/统计口径、适用范围和局限。把原始观察、推断和产品建议分层；呈现相反或不足的证据。模拟反馈仅能作为方法演示，不能充当真实用户反馈或市场规模依据。
4. **交接**：研究发现的新产品决策回到 Grill-Me；只在剩余不确定性不再实质改变下一交付物，或用户选择带明示假设继续时，进入需求文档、设计或实现。

## 文件边界

- `skills/personal-grill-me/SKILL.md`：收窄触发条件，说明何时跳过与如何转入证据验证。
- `skills/demand-evidence-research/SKILL.md`：独立的公开证据挖掘方法；参考文件给出记录格式。
- `INTENTFLOW.md`、`00-项目索引.md`、`skills/README.md`：一致的路由入口。
- `requirements/<name>/`：同一需求贯穿各阶段；证据研究实际发生时才建 `research/`，不预建空目录。具体案例的产品判断只保存在其所属需求目录。

## 验证场景

1. 只有一句模糊想法且目标用户或关键场景未定：先澄清会改变后续产出的决策，再判断是否可写 PRD。
2. 用户与问题已清楚、请求验证痛点：进入证据挖掘；不得重复询问已知事实。
3. 证据充分的成熟产品小改动：跳过两项挖掘，直接进入适当交付物。
4. 搜索不到可靠资料：报告证据不足，不用模拟评论填补。

## 仍未确定

具体需求的开放问题由对应需求目录记录；通用路由不预设任何案例的用户、场景或范围。
