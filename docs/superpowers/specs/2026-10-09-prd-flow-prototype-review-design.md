# PRD—流程—原型联动评审设计

## 目标

让一份需求从 PRD 进入流程和原型后仍然可追踪、可操作、可评审。评审者能够从功能说明找到原型状态，也能从原型状态回到对应的需求和流程链路。

## 交付契约

每个有用户旅程的需求目录按需或固定保留以下产物。`prd/PRD-review.html` 分两次生成：PRD 完成后先用于 PRD-only 评审，流程和原型完成后再用同一路径更新为综合联动评审页：

```text
prd/PRD.md
prd/PRD-review.html
flows/business-flow.md
flows/business-flow.html 或 .svg
flows/interaction-flow.md
flows/interaction-flow.html 或 .svg
design/state-map.md
design/prototype.html 或 Figma frame links
design/verification.md
flows/verification.md
```

PRD 的功能列表至少包含：功能 ID、功能名称、功能流程、原型图/状态、功能描述、数据策略、特殊场景和依赖项。详细功能说明继续补充展示/交互/逻辑、成功条件、失败条件和埋点关联。

## 稳定 ID

| ID | 所属 | 用途 |
| --- | --- | --- |
| `F-xx` | PRD | 功能或行为 |
| `Pxx` | 原型 | 页面或有意义的界面状态 |
| `L-xx` | 交互流程 | 一条可复述的核心链路 |
| `EVT-xx` | 数据埋点 | 一个可统计事件 |

一个功能可以关联多个原型状态和链路；一个原型状态必须关联所属功能，或明确写成上下文状态。

## 两张流程图

### 业务流程图

回答“谁在什么条件下完成什么业务结果”：角色、入口、判断、成功、失败、空状态和退出路径。它不需要展示每个装饰性页面。

### 交互流程图

回答“用户在原型中如何走”：整合所有有意义的 `Pxx` 状态，标注正常、返回、取消、重试、循环、错误和空状态箭头。每条核心路径写成 `L-xx` 并回链到 `F-xx`。每个节点必须嵌入对应原型界面、iframe 或缩略图；如果一张图过大，渲染层可以拆成多个视图，但必须保留一个统一的状态和链路索引。

## 本次规则修正

此前版本把交互流程图实现成了状态关系图，把原型放在右侧预览区，导致流程节点本身看不到对应界面；同时，功能列表有总表但没有规定每个 `F-xx` 下的“功能—原型—说明”细节表；评审 HTML 也只有工具栏和正文，没有章节导航。原因是原交付契约只定义了 ID 映射和双栏预览，没有把“原型界面是流程节点的一部分”“逐功能详细表”“章节定位”写成强制要求。

现在的强制规则是：

1. 交互流程图节点必须包含对应原型界面、iframe 或缩略图，并用箭头标注交互。
2. 每个 `F-xx` 下面必须有三列表格：序号与功能名称、原型图/状态、详细说明。功能名称、功能流程、展示/交互、数据策略、边界/异常/空状态、依赖、成功/失败和埋点统一写入详细说明，不再在表格下重复维护同一组字段；原型列使用 `[[prototype:Pxx]]`，HTML 中展开成真实可操作原型 iframe。
3. PRD HTML 必须生成可点击、可高亮的主要一级章节导航；不得把每个功能和子标题都塞进导航，移动端改为顶部横向导航。
4. 功能表中的原型必须沿用原型的基准画布尺寸（默认 `520x900`；可在原型 `body` 上用 `data-intentflow-viewport="WIDTHxHEIGHT"` 覆盖），在窄列中整体等比缩放；禁止 iframe 因列宽触发响应式重排、裁切或拉伸。

## 双栏联动评审

`prd/PRD-review.html` 在宽屏下显示：

- 左栏：PRD 正文、功能表、业务流程、交互流程和数据说明；
- 左栏正文的功能详情表直接嵌入对应 `Pxx` 可操作原型；
- 右栏：原型状态选择器、状态 ID、缩放、原型 iframe 和映射提示。

交互规则：

1. 左栏滚动到带有 `F-xx`/`Pxx` 映射的标题或功能行时，右栏切换到对应状态。
2. 点击左栏功能、流程节点或状态链接时，右栏切换到对应状态。
3. 右栏切换状态时，左栏定位到对应的功能或标题。
4. 找不到映射时显示“当前内容暂无原型映射”，不创建隐含状态。
5. 原型状态使用 hash 或稳定锚点，便于截图、复核和后续版本追踪。

## 决策记录规则

时序、触发方式、空状态、人工标注和状态拆分等会影响行为的选择必须先记入决策记录，再同步到 PRD、流程和状态图。用户未指定后续时机时，默认采用用户主动进入、可配置复习窗口，不自动推断为立即触发。

## 验证

- `prd/validation.md` 检查 PRD 是否能覆盖核心行为；
- `flows/verification.md` 检查箭头、标签、分支和渲染可读性；
- `design/verification.md` 检查状态、点击路径、空/错/重试状态和 PRD 映射；
- 运行时测试检查双栏结构、状态选择器、状态 map 解析和滚动联动脚本。

本设计只规定通用工作流，不包含任何具体案例的产品假设、题目数据或原型页面。
